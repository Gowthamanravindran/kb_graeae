# Stage 3: Desktop App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Electron desktop app (KB Desktop) with the four approved screens — Library, Map, Ask, Memory — running on a bundled local engine (`kb serve`), so non-developers can analyse, browse, ask, share and pull without a terminal or a Python install.

**Architecture:** `kb serve` is a FastAPI app bound to 127.0.0.1 that wraps the stage 1–2 functions (analyze, ask, push, pull, publish) behind a small JSON API and a background job runner; every request must carry a per-launch secret. Electron's main process starts `kb serve` as a sidecar (dev: `uv run kb serve`; packaged: a PyInstaller binary that also carries Graphify), waits for its ready line, and opens a sandboxed window whose React renderer talks to the API. The renderer never gets Node access; a preload script exposes only the API address, the secret and three safe actions (open link, open file, pick file).

**Tech Stack:** Python: FastAPI, Uvicorn, PyInstaller. Desktop: Electron 33, electron-builder, React 18 + TypeScript + Vite, Tailwind CSS 3 with shadcn/ui-style components on Radix primitives, `@xyflow/react` (React Flow), `mermaid`, `@fontsource/inter`, `@fontsource/jetbrains-mono`. Tests: pytest, Vitest + Testing Library, Playwright (`_electron`) under Xvfb.

**Spec:** `docs/superpowers/specs/2026-10-28-codebase-knowledge-system-design.md` — §2 (kb serve, KB Desktop), §5 (agent), §6 (thumbs → Langfuse score), §9 (four views), §10 items 11–17 and 25, §12 stage 3. Approved mocks: "KB Desktop UI Mocks" canvas (Library, Map, Ask, Memory). Stage 1–2 code: `src/kb/`, `src/kb_registry/`; ledgers in `docs/superpowers/ledgers/`.

## Global Constraints

- `kb serve` binds **127.0.0.1 only**; port 0 (OS-chosen) by default. Every request needs header `X-KB-Token: <secret>` (secret from env `KB_SERVE_TOKEN`, ≥32 random bytes, generated by Electron per launch) and a `Host` of `127.0.0.1:<port>` or `localhost:<port>`; otherwise 401/421. No CORS headers are ever sent.
- Ready line printed on stdout exactly once: `KB_SERVE_READY {"port": <int>}`.
- API prefix `/api`. JSON errors `{"detail": "..."}`; `KbError` → 400 with its message, `LLMUnavailable` → 503 with `"Claude Code is not available: <reason>"`, `RegistryUnavailable` → 503.
- Long operations (analyze, ask, push, pull, retrace, run suggestion) are **jobs**: `POST` returns `{"job_id"}`; `GET /api/jobs/{id}` → `{"id", "kind", "state": "queued"|"running"|"done"|"failed", "step": str, "progress": float 0–1, "result": object|null, "error": str|null}`. Jobs live in the server process (they survive a renderer reload). At most one analyze per project+branch at a time (second → 409 with the running job id).
- Desktop workspace file: `$KB_HOME/desktop.json` = `{"projects": [{"config_path": "<absolute kb.yaml>"}]}`.
- Electron window: `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, `webSecurity: true`; navigation away from the app and `window.open` are blocked (http/https links go to the system browser via `shell.openExternal`); CSP `default-src 'self'; connect-src http://127.0.0.1:*; img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self'`.
- Preload exposes exactly `window.kb = { baseUrl: string, token: string, openExternal(url: string): Promise<void>, openFile(path: string, line?: number): Promise<void>, pickFile(filters?: {name: string, extensions: string[]}[]): Promise<string | null> }`.
- Visual design follows the approved mocks: background `#F6F6F4`, surface `#FFFFFF`, border `#E3E3DF`, ink `#18191C`, muted `#5E6168`, accent `#2F5BD3` / soft `#E8EEFC`, published `#1F7A4D` on `#E6F4EC`, stale `#8A5200` on `#FFF4E0`, private `#3F4247` on `#EEEEEB`; Inter for UI, JetBrains Mono for paths; sidebar with Library / Map / Ask / Memory, a project switcher card, and a status footer (Registry, Claude Code, Langfuse). Fonts are bundled, never fetched at runtime.
- Plain-English labels in the UI ("Analyse a branch", "Share", "Pull", "Ask this"); no internal ids except in monospace detail lines.
- Packaged engine: one PyInstaller *one-folder* binary `kb-serve` that runs `kb serve` and, when started as `kb-serve --run-graphify <args>`, runs Graphify's CLI (so users need no Python or Graphify install). Claude Code itself is still the user's own `claude` install (spec §2 constraint).
- Commit only, never push (user instruction).

## Review Focus

1. **Another local process or a web page calls `kb serve`** (wrong/missing token, DNS-rebinding `Host`) — rejected 401/421 and nothing runs. → Task 1 `test_requests_need_token_and_local_host`.
2. **The engine fails to start** (binary missing, crashes, port never announced) — the window shows "KB engine didn't start" with the last log lines and a Retry button, not a blank window. → Task 9 `sidecar_failure_shows_error_screen` (Playwright).
3. **Claude Code not installed or not signed in** — Library, Map and Memory still work; Ask shows a banner explaining how to sign in, and a job that needs Claude fails with that message (not a stack trace). → Task 3 `test_ask_job_fails_with_claude_message`, Task 13 `ask_shows_claude_banner`.
4. **User leaves the Ask screen (or reloads) while a 60-second answer runs** — the job keeps running and the answer is there on return. → Task 2 `test_job_survives_and_is_listed`, Task 13 `ask_resumes_running_job`.
5. **Citation "open file" for a path outside the analysed checkouts** — refused; nothing is opened. → Task 5 `test_resolve_citation_refuses_escape`.
